Cloudrive connects Google Drive, Dropbox, OneDrive and any S3-compatible bucket to a
**workspace**, then lets people browse them as one drive and lets any S3 client
(aws-cli, rclone, SDKs) read and write them through a single S3-compatible gateway.
Files stay where they are: Cloudrive stores credentials and mappings, never copies of
your data.

## What is in the repository

| Path          | What it is                                                                                      |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `apps/server` | Go API (Fiber v3, Bun on Postgres, Authula auth). Also runs the S3 gateway and serves the SPA.  |
| `apps/web`    | The whole frontend as one Vite SPA (React 19, TanStack Router/Query/Form, Tailwind, shadcn/ui). |
| `apps/docs`   | This site (Next.js + Fumadocs).                                                                 |
| `docs/`       | Design records: ERD, provider OAuth PRD, S3 gateway notes.                                      |

## Core concepts

- **Organization**: the tenant. Members have the role `owner`, `admin` or `member`.
- **Workspace**: belongs to one organization and holds storage accounts, S3 credentials
  and S3 buckets. Workspace members have the role `admin`, `member` or `viewer`.
- **Provider**: a catalog entry (`google_drive`, `onedrive`, `dropbox`, `s3_compatible`)
  that decides which connector talks to the storage.
- **Storage account**: one connected account of a provider, bound to one workspace. Its
  credentials live encrypted in a separate vault table.
- **S3 bucket mapping**: a bucket name the gateway serves, pointing at one storage
  account and an optional prefix inside it.
