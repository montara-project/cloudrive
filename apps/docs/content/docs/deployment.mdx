## The image

`apps/server/Dockerfile` builds from the **repository root**, because it also builds the SPA
from the pnpm workspace:

```sh
docker build -f apps/server/Dockerfile -t cloudrive-api .
```

| Stage     | Does                                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `web`     | `node:24-alpine`: `pnpm install --frozen-lockfile --filter @cloudrive/web`, then `vite build`.                                                               |
| `builder` | `golang:1.26-alpine`: builds `api` and `migrate` (`CGO_ENABLED=0`, linux/amd64).                                                                             |
| runtime   | `alpine:3.21`, non-root user `cloudrive`: binaries, `migrations/`, `templates/`, `public/`, the SPA in `/app/web` (`SPA_DIR=/app/web`), and `entrypoint.sh`. |

The build context is filtered by the root `.dockerignore`, shared with the docs image: no
`node_modules`, build output, or `.env` files.

<Callout type="warn">
  The image's `go build` sets `GOARCH=amd64`. It runs on arm64 hosts only through emulation.
</Callout>

## Running it

```sh
docker run -p 8080:8080 -p 9000:9000 \
  -e MACHINE_ID=1 -e APP_SECRET=… -e DB_DSN=… \
  -e CLIENT_URL=https://cloudrive.example.com -e SERVER_URL=https://cloudrive.example.com \
  -e RESEND_API_KEY=… -e RESEND_FROM_EMAIL=… -e RESEND_DEBUG_TO_EMAIL=… \
  -e STORAGE_CREDENTIALS_KEYS=v1:<base64-32-byte-key> \
  -e MIGRATE_ON_BOOT=true \
  cloudrive-api
```

- `entrypoint.sh` maps each **non-empty** environment variable to its flag, appended after
  the image defaults (`--env=production --port=8080`). No `.env` is baked into the image.
- Port 8080 serves the web app, the REST API and `/health`; port 9000 is the S3 gateway.
- The healthcheck polls `GET /health` every 30 seconds.
- With one origin, set `CLIENT_URL` and `SERVER_URL` to the same public URL, and add it to
  `CORS_ALLOWED_ORIGINS` so Authula accepts its `redirect_to` / `callback_url`.
- Behind a reverse proxy, set `TRUSTED_PROXIES` so logs and rate limiting see real client IPs.
  The client IP is the rightmost `X-Forwarded-For` entry that is not a trusted proxy, so list
  every hop: behind Cloudflare, add [its IP ranges](https://www.cloudflare.com/ips/) too, or
  every request appears to come from a Cloudflare edge address.
- Running more than one replica: keep `MIGRATE_ON_BOOT=false` and run migrations as a
  separate step: `docker run --rm --entrypoint /app/migrate cloudrive-api --db-dsn=… up`.

## Release

Releases follow [release-it](https://github.com/release-it/release-it) with conventional
commits, in three workflows:

1. **Release Prepare** (`release-prepare.yml`, run manually on `main`): bumps the version
   (`auto` from the commits since the last `v*` tag, or `patch`/`minor`/`major`), updates
   `CHANGELOG.md`, syncs every `apps/*/package.json` version (`scripts/sync-versions.mjs`),
   and opens a `chore: release vX.Y.Z` pull request.
2. **Release Publish** (`release-publish.yml`): when that `release/*` PR merges into `main`,
   tags the merge commit and creates the GitHub release, then dispatches the release workflow.
3. **Release** (`release.yml`): builds and pushes both images to GHCR. It also runs on a
   pushed `vX.Y.Z` tag, or manually with an extra tag.

| Image                            | Dockerfile               |
| -------------------------------- | ------------------------ |
| `ghcr.io/<owner>/cloudrive/api`  | `apps/server/Dockerfile` |
| `ghcr.io/<owner>/cloudrive/docs` | `apps/docs/Dockerfile`   |

Tags per release: `1.2.3`, `v1.2`, `latest`, and `sha-<short>`.

Preview the next version locally with `pnpm release:prepare --dry-run`.

<Callout type="warn" title="Repository setting">
  Release Prepare opens its PR with `GITHUB_TOKEN`: enable **Settings → Actions → General → Allow
  GitHub Actions to create and approve pull requests**.
</Callout>

## Docs site

`apps/docs` builds its own image (Next.js standalone output, port 3000):

```sh
docker build -f apps/docs/Dockerfile -t cloudrive-docs .
docker run -p 3000:3000 cloudrive-docs
```

For local work: `pnpm dev:docs` (port 3001) or `pnpm build:docs`. The site also serves
`llms.txt`, `llms-full.txt`, and per-page Markdown for AI tools.
