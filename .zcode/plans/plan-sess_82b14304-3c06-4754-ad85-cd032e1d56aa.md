# Onboarding Flow untuk User Tanpa Organization

## Latar belakang (hasil eksplorasi)
- Saat ini **tidak ada onboarding sama sekali**: user tanpa org mendarat di dashboard dengan empty state tersebar, dan `use-workspace-context.ts:64` punya fallback `orgId ?? ''` yang membuat query workspace berjalan dengan id kosong.
- Org dibuat via `POST /v1/organizations` → `CreateWithOwner` (org + member owner dalam 1 transaksi). Tidak ada provisioning default saat signup.
- Stack frontend `apps/app`: vinext (Next-style file routing), Tailwind v4 + shadcn-style kit di `components/ui/`, TanStack Form + Zod (`hooks/form.tsx` → `useAppForm`), TanStack Query + axios services (`lib/api/`), nuqs, motion, sonner. **Belum ada wizard/stepper** — dibuat baru.
- Backend `apps/server`: Go/Fiber + `database/sql` + lib/pq, raw SQL, golang-migrate (migration berikutnya `000006_`), konvensi enum = `text + CHECK IN (...)`, multi-value = `jsonb` (lihat `providers.capabilities`), wiring handler → repo (tanpa service layer untuk CRUD), `Executor` pattern untuk transaksi.
- Keputusan user: **wizard = survey (wajib) + buat organization**; skema DB pakai **kolom jsonb**.

## 1. Database — migration `000006_create_onboarding_survey` (apps/server/migrations/)

Buat via target migrate di `apps/server/Makefile` (pola `migrate create -seq -ext=.sql -dir=./migrations`).

**`000006_create_onboarding_survey.up.sql`** — mengikuti house style (`uuidv7()`, `timestamptz`, section comment, constraint bernama):

```sql
CREATE TABLE IF NOT EXISTS "onboarding_surveys" (
    "id" uuid PRIMARY KEY NOT NULL DEFAULT uuidv7(),
    "user_id" uuid NOT NULL,
    "referral_source" text NOT NULL CHECK ("referral_source" IN
        ('search_engine','social_media','recommendation','community','github','other')),
    "referral_source_detail" text CHECK (length("referral_source_detail") BETWEEN 1 AND 255),
    "use_cases" jsonb NOT NULL CHECK (jsonb_typeof("use_cases") = 'array'),
    "use_case_detail" text CHECK (length("use_case_detail") BETWEEN 1 AND 255),
    "created_at" timestamptz NOT NULL DEFAULT now(),
    "updated_at" timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT "uq_onboarding_surveys_user" UNIQUE ("user_id"),
    CONSTRAINT "fk_onboarding_surveys_user" FOREIGN KEY ("user_id")
        REFERENCES "users" ("id") ON DELETE CASCADE
);
```

Catatan postgres-best-practices: `UNIQUE (user_id)` sekaligus menjadi index untuk FK `user_id` (tidak perlu index terpisah — hindari redundansi); upsert nanti pakai `ON CONFLICT (user_id) DO UPDATE` dengan conflict target eksplisit + `RETURNING`. Tradeoff yang disadari: opsi `referral_source` dibekukan di CHECK (perubahan opsi = migration kecil), konsisten dengan konvensi repo (`organization_members.role`, `storage_accounts.status`).

**`.down.sql`**: `DROP TABLE IF EXISTS "onboarding_surveys";`

## 2. Backend Go (apps/server)

1. **Model** `internal/models/onboarding_survey.go` — tag `db`/`json` mengikuti `organization.go`; `UseCases []byte` untuk jsonb dengan trik lib/pq (kirim sebagai JSON text, bukan bytea — lihat komentar di `repositories/provider.go:219-224`).
2. **DTO** `internal/dtos/onboarding.go` — `CreateOnboardingSurveyRequest{ReferralSource string, ReferralSourceDetail *string, UseCases []string, UseCaseDetail *string}` + validasi mirror constraint DB (referral_source ∈ set, use_cases min 1 & setiap item ∈ set, detail ≤ 255).
3. **Repo** `internal/repositories/onboarding_survey.go` — embed `BaseRepository`, satu metode publik `UpsertByUser` → privat `upsertByUserExec(exc Executor, ...)` (pola `Executor` agar kompatibel transaksi), timeout 3s, `errtrace`, `uuid.NewV7()` untuk insert. SQL:
   ```sql
   INSERT INTO "onboarding_surveys" (...) VALUES ($1,...)
   ON CONFLICT ("user_id") DO UPDATE
   SET "referral_source" = EXCLUDED."referral_source",
       "referral_source_detail" = EXCLUDED."referral_source_detail",
       "use_cases" = EXCLUDED."use_cases",
       "use_case_detail" = EXCLUDED."use_case_detail",
       "updated_at" = now()
   RETURNING "id","created_at","updated_at";
   ```
   Upsert = idempoten, aman untuk retry bila langkah berikutnya gagal.
4. **Handler** `internal/handlers/onboarding.go` — `Submit`: `currentUser(c)` → `bindBody` → validasi → upsert → respond JSON (gaya `organization.go`).
5. **Wiring**: daftarkan repo di `internal/repositories/factory.go`, handler di `internal/handlers/factory.go`, route di `cmd/api/routes.go`: `r.Post("/v1/onboarding/survey", m.Authorization(), h.Onboarding.Submit)`.

## 3. Frontend (apps/app)

### 3a. API layer
- `lib/api/dtos/onboarding/schema.ts` — Zod schema + **konstanta opsi** (satu sumber untuk UI & schema):
  - `REFERRAL_SOURCES`: `search_engine, social_media, recommendation, community, github, other`

- `lib/api/services/onboarding.ts` (POST `/v1/onboarding/survey`) + `lib/api/queries/onboarding.ts` (mutationOptions) — pola sama dengan `services/organization.ts` & `queries/organization.ts`.

### 3b. Routing & gate
- **Route baru** `app/(onboarding)/onboarding/page.tsx` — di luar grup `(dashboard)` → full-screen tanpa sidebar. Gate di halaman: tidak ada session → replace `/`; org list loaded && non-empty → replace `/dashboard`; selama loading → `SessionLoading` (pola `login-gate.tsx` + `(dashboard)/layout.tsx`).
- **Gate di dashboard** `app/(dashboard)/layout.tsx` — setelah session ada, query `queries.organizations.list({limit:100})` (query key sama dengan `use-workspace-context.ts` → cache bersama): loading → `SessionLoading`; kosong → replace `/onboarding`; ada isi → render `SidebarLayout` + children. Ini sekaligus menutup bug `orgId ?? ''`.
- `login-gate.tsx` & `auth/callback/page.tsx` tidak diubah (tetap ke `/dashboard`; gate dashboard yang membelokkan).

### 3c. Wizard UI — `components/block/onboarding/`
- **`onboarding-wizard.tsx`** — orchestrator: state langkah 1→3, simpan jawaban survey antar langkah, tombol Back/Continue.
- **`stepper.tsx`** — progress dots/segments + "Step X of 3" (aria-current, accessible).
- **`step-referral.tsx`** — "Where did you hear about Cloudrive?" — opsi sebagai **selectable cards** (radix radio-group di bawahnya untuk a11y, icon lucide per opsi); field text muncul saat `other`. Wajib.
- **`step-use-cases.tsx`** — "What will you use Cloudrive for?" — checkbox cards multi-select (min 1); field text saat `other`. Wajib.
- **`step-organization.tsx`** — "Create your organization" — reuse `CreateOrganizationSchema` (name, slug auto, logo) & mutation yang sama dengan `components/block/organizations/form.tsx` (refactor kecil bila perlu agar logika bisa dipakai ulang).
- **Submit akhir (urutan)**: (1) POST survey — wajib berhasil (gagal → toast error, tetap di langkah; upsert aman untuk retry), (2) POST organization — wajib berhasil, (3) success toast → `router.replace('/dashboard')` (org baru otomatis jadi `organizations[0]` fallback di workspace context).
- Field form: pakai `useAppForm` + Zod per langkah (pola `organizations/form.tsx`); tambah `components/block/form/radio-group-field.tsx` mengikuti pola field lain untuk kebutuhan step 1.
